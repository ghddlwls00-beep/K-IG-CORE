# 명령서 대조표 — 사장님의 원래 감사 명령서, 요구 하나하나를 증거와 대조

`====` 로 둘러싼 부분만 복사해서 **새 세션**(K-IG-CORE 폴더)에 붙이세요.

## 소유자용 안내

- **소유자 결정 (2026-09-24 새벽, 점검 세션 채팅)**: 바탕화면 `PROMPT-출시전-최종재검사.md` 의 다섯 명령(A~E) 가운데
  **C 만 한다** — "아니다 b빼고 c만 넣자". A(결함 심기 시험) · B(사파리 엔진 전체 검사) · D(사람 테스트) · E(신고 창구 · 소수 출시 준비)는 하지 않는다.
- **무엇을 하나**: 9/18 에 사장님이 주신 감사 명령서(§0 · §1~§24)의 요구를 **한 줄에 하나씩** 적고, 옆에
  "했다 / 부분 / 안 했다" 와 그 증거 파일을 붙입니다. **빈칸이 곧 안 한 일입니다.**
- **언제**: 최종 출시 관문([`PROMPT-최종-출시관문.md`](PROMPT-최종-출시관문.md))이 끝난 뒤. 그 관문의 새 기록이 증거입니다.
- **누가**: 감사 · 수정을 돌린 세션이 아닌 **새 세션**이 좋습니다. 다만 같은 AI 계열이라 독립 검토는 아닙니다.
- **얼마나**: 반나절쯤. 사장님은 끝에 나온 표의 "없음 · 부분" 목록만 보시면 됩니다.
- B · D 를 빼서 **실제 아이폰 · 사파리에서 확인하는 검사는 없습니다** — 자동 검사는 모두 크롬 계열(Edge)로 합니다.

  드러났다 (findings-log 의 CONTENT-VOID-0918).

■ 표를 만들어라 — 섹션 단위가 아니라 요구 단위로
  명령서의 요구 하나하나를 한 줄씩:
    § 번호 / 요구(원문 요약) / 무엇을 했나 / 증거 파일(경로) / 결과(수치) / 못 한 것
  예: §4 의 "double-clicking" 한 줄, "repeatedly pressing Play" 한 줄, "switching lessons quickly" 한 줄.
  §13 의 "long-session stability", "possible memory leaks", "screen-reader compatibility",
  "keyboard navigation" 같은 것도 하나씩 따로.

  증거 파일이 없으면 "했다" 로 적지 마라. 빈칸으로 둬라.
  증거 파일이 있어도 그 파일이 그 요구를 실제로 검사했는지 열어서 확인해라. 파일 이름만 보고 판단하지 마라.
  §3 의 "데이터에는 있는데 화면에서 도달할 수 없는 콘텐츠" 는 9/18 감사가 놓친 것(BUG-024)이다.
  7단계 7-1 c 의 check-unreached-data.cjs 가 이번 기록으로 실제로 돌았는지 특히 확인해라.
  같은 AI 가 도구를 고치고 그 도구로 검사했다 — 도구가 "실패를 잡는지" 증명한 기록(proof-summary.cjs 등)이
  있는 검사인지도 줄마다 적어라.

■ 표 맨 위에 요약
  요구 N개 중: 증거 있음 N · 부분 N · 없음 N · 소유자 몫 N
  "없음" 과 "부분" 인 요구를 따로 목록으로.
