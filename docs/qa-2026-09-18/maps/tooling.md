### 3.3 `docs/qa-2026-09-18/scripts/lib/profile.cjs`

- `SOURCE = %TEMP%\kig-audit-licensed-profile` (line 19).
- `cloneProfile(name, {fresh})` (32-47) copies with `robocopy /E` into `%TEMP%\kig-audit-0918-<name>` and skips cache directories (line 20) and lock files. - A clone carries the same licence token, cookies and device id. No new device is registered. The server has no concurrent-use check (`deviceStorage.ts` only updates `lastSeenAt`).

## 6. Audio: what is spoken, clip URL, fallback, generator, manifests

### 6.1 Clip URL derivation

```
spoken string S (view-specific: English sentence, row, word; VOCA: vocaSpeechForm(word))
 → clean = normalizeUnifiedSpeechText(S)                    (speech.ts:501-503 cleanText)
 → key   = `${clean.length.toString(36)}-${hex(fnv1a-variant)}${hex(second hash)}`   (unifiedSpeech.ts:21-35)
 → URL   = /audio/azure-ava/v1/<key>.mp3                    (unifiedSpeech.ts:37-39)
```

- `shouldUseUnifiedSpeech()` is false only on `/cnn` paths, so all six in-scope courses use Ava clips. The original recordings (`audio[].src`) are **not played** by the player in these courses (F-02; `probe-missing-audio` requested only `audio/azure-ava/v1/…`).
- `speakText` → `speakWithToken` (`speech.ts:959-1007`) → `playUnifiedClip` (`755-841`), which sets the shared `<audio>` src to the clip, clamps `playbackRate` to 0.5–2, and plays.
- Queue playback is `playSentenceQueue(sentences, {startIndex, gap=250, loop, onProgress})` (`speech.ts:1110`), with `jumpToQueueIndex`, `nextSentence` and `previousSentence` (1183-1210).

### 6.2 Fallback chain (how a missing clip looks in CDP)

1. The `<audio>` `error` event, or a rejected `play()` promise, calls `failAvaPlayback` (`speech.ts:783-803`). It pauses, removes `src`, calls `load()`, and runs `startLegacyEngine`.
2. The legacy engine (`966-1002`) segments by language and splits into ≤200-character chunks. For each chunk (`937-956`):
   - If `speechSynthesis` exists and not in KakaoTalk or an in-app browser, and a voice exists for the language → `playChunkViaSynthesis` (`845-927`), which logs `tts.speak` in the harness hook. A 1.5 s watchdog switches to the stream path if the voice stays silent.
   - Otherwise → `playChunkViaStream` (`708-752`), which **requests the same clip URL again** and on error calls `finishRun(error)`, i.e. silence plus `onError`.
3. **Detection rule for drivers:**
   - clip OK = the clip path has `play-resolved`, `playing`, and `ended` or advances, with an HTTP 206/200 `audio/*` response;
   - clip missing = a 403/404 response on `/audio/azure-ava/v1/<key>.mp3`, or an `error` event, or a `tts.speak` entry for that text;
   - wrong clip = the requested path differs from `expectedClip(expected text)`.
4. Headless Edge is launched with `--mute-audio` and autoplay allowed. `playing` and `ended` fire, but **audibility is not measurable**.

## 10. CDP driver recipe: exhaustively exercising one lesson

This is written for `lib/harness.cjs`. The course-specific steps and exact controls are in the sibling maps (§4 and §10 of `voca.md`, `grammar1.md`, `grammar2.md`, `listening.md`, `reading.md`, `student.md`). This skeleton is shared.

### 10.1 Before the lesson loop (once per driver)

1. `const browser = await H.startBrowser("<driver-name>", <unique port 9410+>)`. Run `check-clone-licence.cjs <driver-name>` first and require `plan: "LIFE"`, `paywall: false`, `passage: true`.
2. `const tab = await H.openTab(browser, { clean: true })`. The audio hook and `CLEAN_STORAGE` run on every navigation.
3. Load expectations in node, never from the page:
   - `data = JSON.parse(content/lessons/<c>/<id>.json)`; for ld also `ld_english_scripts.json[base]`
   - `pres = loadTs(curriculumPresentation.ts).formatLessonPresentation(c, data)`

   - `free = isFreePreviewLesson(c, id)`
   - the expected spoken strings and `expectedClip(s)` for each
4. Open `H.jsonl(path.join(H.OUT, "<driver>.jsonl"), r => r.course+"|"+r.id+"|"+r.viewport)` and skip keys already done.

### 10.2 Per lesson × viewport (desktop, tablet, mobile)

1. **Redirect check.** If `isRedirectedLesson(c, id)`, load the URL, assert the final `href` ends with `/<c>/<ctx.pair.id>`, record it, and stop for this id (its screen is covered by the pair).
