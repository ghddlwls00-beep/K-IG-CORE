# 공통 학습 엔진 — 설계 v1 (2026-09-27, 옆 세션 검토와 합침)

> 상태: **v1**. v0(같은 날 새벽)에 옆 세션("3차 점검 수정")의 학습법 · 화면 전수 점검(main `dacc980`: `docs/qa-2026-09-18/학습법-화면-0927/` 의 사장님-요약 · 계획 D02 · D04 · D12 · D20 · D21 · D32 · A11 · "나중 — 날을 넘기는 복습")을 합쳤다.
> 같은 AI 계열이 쓰고 점검한 문서라 **독립 검수가 아니다**.
> 사장님 결정(D8): 날을 넘기는 복습 체계는 한 과정 전용이 아니라 **모든 섹션이 함께 쓰는 엔진**으로 한 번만 만든다. 첫 적용은 PASS-OFF GRAMMAR. 보호자 보고는 만들지 않는다(D9).
> 원칙: 기존 섹션의 문장 · 번역 · 음성은 바꾸지 않는다. 섹션마다 어댑터로 붙이고, 붙일 때마다 그 섹션만 화면 · 소리 · 채점 점검을 다시 한다.
> **섹션마다 공부 방법은 다르다(사장님 확인, 2026-09-27).** 레슨 안의 단계(VOCA 낱말 · LISTENING 받아쓰기 · READING 이해 · GRAMMAR 영작 · STUDENT 받아쓰기·말하기 · PASS-OFF 예문·규칙·형태·영작)는 섹션 것이다. 엔진은 **날을 넘기는 부분만** 맡는다: 날짜 · 복습 일정 · 통과 판정 · 하루 분량 · 오답노트 · "내 답도 맞아요" 신고.

## 2. 기록 — 모든 섹션이 같은 모양 (`src/lib/learning/`)

```ts
type Day = string;            // "2026-09-27" — 한국시간, 하루는 오전 4시에 바뀜(서버 시각 기준)
interface LessonDone { at: string | null; day: Day | null }       // null = 옛 true(날짜 모름)
interface Attempt {
  day: Day; at: string;                                           // 서버가 받은 시각으로 day 를 다시 계산
  correct: boolean;                                               // 섹션 채점기의 판정(부분 정답은 false)
  firstTry: boolean;                                              // 그 문항을 그날 처음 푼 것인가
  help: "none" | "hint" | "tiles" | "reveal";                     // 도움을 받았으면 통과 횟수에 안 셈
  mode: "typed" | "voice" | "tap";
  where: "lesson" | "review";
  pending?: boolean;                                              // "내 답도 맞아요" 보류
}
interface ItemState {
  lessonId: string; kind: string;
  stage: "learning" | "passed";                                   // 통과 뒤에도 유지 확인은 계속
  firstDay: Day; dueDay: Day; step: number;                       // step 0=R1(다음 날) 1=R2 2=R3 3+=유지
  passDays: Day[];                                                // 도움 없이 첫 시도에 맞힌 서로 다른 날(첫날 제외)
  lastDay: Day | null; lastCorrect: boolean | null; lapses: number;
}
interface CourseRecord {
  v: 1; course: string;
  lessons: Record<string, LessonDone>;
  items: Record<string, ItemState>;                               // 열쇠 = 문항 열쇠(아래)
  log: (Attempt & { item: string })[];                            // 최근 것만(문항마다 마지막 8개)
  reports: { item: string; answer: string; day: Day; status: "pending" | "accepted" | "rejected" }[];
  lastStudyDay: Day | null;
}
```

**문항 열쇠**: 과정 안에서 바뀌지 않는 문자열. PASS-OFF 는 문항 id(`pg02-1:p4`). 기존 섹션은 `레슨id#순번`(데이터에 있는 순서, 1부터) — 문장 · 번역 · 음성을 바꾸지 않으므로 순번이 안 바뀐다. 섹션이 내용을 바꾸게 되면 그 섹션 기록의 버전을 올린다.

**기록 함수**(섹션은 이것만 부른다 — 다른 형식을 새로 만들지 않는다):
- `markLessonDone(course, lessonId)` — 첫 완료 날짜를 남긴다(다시 완료해도 첫 날짜 유지).
- `recordAttempt(course, itemKey, { lessonId, kind, correct, firstTry, help, mode, where })`.
- `reportMyAnswer(course, itemKey, answer)` — "내 답도 맞아요".
- 기기 저장은 과정마다 `localStorage` 한 칸(`kig-learning:<course>`). 이용권이 있고 서버 저장이 켜진 과정은 단계 · 회차가 끝날 때 묶어서 보낸다.

## 3. 일정과 통과

- **들어오는 문항**(어댑터가 정함, 아래 표): 레슨을 끝낸 날(D1) 그 레슨의 대상 문항이 `step 0`, `dueDay = D1 + 1`.
- **일정**: R1 = D1+1(다음 날 확인) → R2 = +2일(D4 쯤) → R3 = +4일(D8 쯤) → 통과 조건을 채우면 유지 확인 +21 · +60 · +120일. 늦게 풀면 그 푼 날을 기준으로 다음 간격을 잰다.
- **틀리면**: 그 문항만 `step 0`, 다음 날. `lapses` +1. 통과했던 문항이 유지 확인에서 틀리면 통과 표시를 지우고 레슨에 "복습 필요".
- **통과(기본값, 어댑터가 바꿀 수 있음)**: 첫날을 뺀 **서로 다른 날 3번** 도움 없이 첫 시도 정답, 그중 한 번은 첫날로부터 **6일 이후**, 마지막 시도도 정답. 요소 문항(PASS-OFF 형태 찾기 · VOCA 낱말)은 **2번**.
- **하루 분량**: 과정마다 **약 10분**(600초 ÷ 문항 종류별 초). 넘치면 남은 것은 다음 날로(늦은 것 먼저 · 다음 날 확인 · 나머지 순). 두 번째 복습부터 레슨을 섞는다.
- **재학습이 많을 때**: 통과 전 문항이 60개를 넘으면 새 레슨보다 "복습 먼저"를 권한다(잠금 아님).
- **복귀 코스**: 마지막 공부로부터 3일 이상 지나면 "복습 10개부터"(가장 늦은 것 10개), 끝나면 평소대로.
- **같은 날 두 기기 기록이 다르면** 틀린 쪽을 쓴다.
- **말로 답한 것**(mode=voice): 글자로 바꿔 채점한 결과를 쓰고, 통과 횟수에도 넣는다(다른 섹션과 같은 마이크 흐름). 음성 인식이 문법을 고쳐 받아쓸 위험은 사용자 기록이 생기면 다시 본다.

## 4. 저장과 보호

- 기기와 서버의 모양이 같다(§2). 서버는 STUDENT 진도와 같은 방식: R2 비공개 객체 `private/learning/<course>/<sha256(이용권)>.json`, AES-256-GCM, 로컬 대체 저장소 `data/learning-<course>.json`(이 컴퓨터에서 시험).
- 서버가 판정한다: 받은 시도의 날짜는 서버 시각으로 다시 계산하고, 열리지 않은 레슨의 기록은 받지 않는다(순서 잠금 과정).
- "오늘 할 일" 페이지: 서버가 이용권 확인 → 기록 읽기 → **오늘 낼 문항의 데이터만** props 로. 유출 · 잠금 탐침 대상에 넣는다.
- 무료 체험: 기기에만. 이용권을 넣으면 한 번 서버로 합친다.
- 기존 섹션: D04 결정 전에는 기기에만(지금 VOCA · GRAMMAR · LISTENING · READING 진도와 같음). 결정되면 같은 모양 그대로 서버로.

## 6. 옆 세션이 지금 할 것

- 섹션을 고칠 때 완료 · 시도 기록은 `src/lib/learning/record.ts` 의 함수로 남긴다(설계 세션이 곧 main 에 넣음 — 들어오기 전에는 새 형식을 만들지 말고 기다렸다가 붙인다).

## 8. 단계 2-나 — 복습 화면 · 서버 저장 · 구성도 다시 채우기 (PASS-OFF 먼저, 다른 과정이 그대로 가져다 씀)

옆 세션: "복습 화면은 그쪽 PASS-OFF 것이 나오면 붙이겠습니다" → **과정에 매이지 않는 틀 + 과정별 문항 그리기**로 만든다.

1. **서버 저장**(`src/lib/learning/serverStore.ts`, server-only): STUDENT 진도와 같은 방식 — R2 비공개 `private/learning/<course>/<sha256(이용권)>.json`, AES-256-GCM, 로컬 대체 `data/learning-<course>.json`(.gitignore), 이용권 키별 쓰기 줄 세우기. 켜는 과정 목록 `SERVER_LEARNING_COURSES = ["passoff-grammar"]`(D04 결정이 나면 더함).
2. **API** `src/app/api/learning/[course]/route.ts`: 이용권 세션 필수 · 그 과정을 여는 이용권만(`planOpensCourse`) · 쓰기 속도 제한(STUDENT 와 같게).
   - POST `{ record }` → 서버 기록과 `mergeRecords` → 저장(바뀐 때만) → `{ record, plan, items }`.
   - `plan = planDay(record, learningDay(서버 시각), profile)`. `items` = **plan 에 든 문항의 데이터만**(과정 어댑터의 서버 함수가 레슨 파일에서 꺼냄 — 문항 id → 레슨 → 블록 → 문항). 순서 잠금 과정은 **열린 대주제의 문항만**.
   - 무료 체험(이용권 없음)은 서버를 안 씀: 무료 레슨(pg01-1 · pg01-2)의 문항만, 기기 기록으로, 문항 데이터는 무료 레슨 쪽 데이터에서.
3. **복습 화면** `src/app/passoff-grammar/review/page.tsx`(정적 경로가 `[lesson]` 보다 먼저) + 공용 클라이언트 `src/components/learning/ReviewSession.tsx`.
   - 기기 기록을 올려 합친 뒤, 받은 plan 을 차례로 낸다.
   - 문항 그리기는 과정이 넘기는 `renderItem(kind)` — PASS-OFF 는 ④ 영작 카드(타이핑 · 마이크, 사다리)와 ③ 형태 찾기 카드를 그대로 쓰되 `where: "review"` 로 기록.
   - **다음 날 확인**(reason "next-day" 묶음)은 시험처럼 다 풀고 결과를 한꺼번에 보이고, 틀린 문장은 끝에서 바로 사다리로 다시.
   - 나머지는 문항마다 바로 결과.
   - 끝 화면: 오늘 푼 수 · 통과한 문장 수 · 내일 올 수 · "오답노트 보기".

- 화면 틀: `ReviewSession`(복습) — 틀린 **첫** 답은 바로 기록하지 않고 쥐고 있다가 학습자가 넘어갈 때(다음 문항 · 결과를 떠날 때 · 끝 · 쪽을 떠날 때) 그대로 기록한다. 그 전에 "내 답도 맞아요"를 누르면 그 신고가 그날의 답이 된다(엔진 pending — 맞음도 틀림도 아님 · 진도 안 깎임 · 내일 다시). 이미 기록된 답에 대한 신고는 신고만 남고 그날의 틀림은 그대로. 다음 날 확인 결과를 서버로 올리는 때는 '결과가 보일 때' → '결과를 떠날 때'(결과 화면의 신고가 같이 가게). 끝 화면에 '오답노트 보기 N문항'. `WrongNotes`(오답노트 — 새 파일): 레슨별 목록 → 펼치면 문항마다 한국어(지시문) · 내 답 · 틀린 횟수 → '지금 다시 풀기'(과정 카드 mode "notes"). `MyAnswerReport`(새 파일): 틀린 결과 옆 단추 하나 — 복습 결과 · 과정 카드 · 오답노트가 같은 모양. 과정 카드는 `CourseItem` 으로 그려 틀의 기록 함수가 렌더 중에 불리지 않게(react-hooks/refs 오류 — E1 판에도 있던 것 — 0).
- 다른 과정이 붙일 때: `ReviewCourse` 에 `notesHref` · `lessonTitle` 선택 칸, `renderItem` 이 받는 `mode` 에 "notes" · `onReport` · `reported` 가 더해짐. 과정 카드는 틀린 결과 옆에 `MyAnswerReport` 를 두고 `onReport({ answer, mode })` 를 부르면 된다.

## 12. 단계 2-나 E2 수정 — 점검 반영(2026-09-28)

같은 AI 계열이 점검하고 같은 계열이 고친 것이다(독립 검수 아님). 엔진 핵심(`day.ts` · `engine.ts` · `record.ts` · `types.ts`)은 그대로이고, 기존 6과정의 화면 · 채점 · 기록은 바뀌지 않는다(공통 부품 `lessonGate` · `LessonEndBar` 에는 선택 칸 `quietNext` 하나 — 걸지 않은 과정은 그대로).

**엔진 쪽(과정에 매이지 않음)**
- 오답노트 '지금 다시 풀기'는 **오늘 낼 차례이고 오늘 복습에서 아직 안 푼 문항을 내지 않는다**(`practice.ts` `practiceWaits` — 그 행에 '복습할 차례예요', 다시 풀기는 그 레슨의 나머지만). 연습에서 사다리로 정답을 보고 같은 날 복습에서 답하면 그 답이 그날 첫 답이라 통과 날로 세어졌다(엔진으로 보임: effect right · passDays [오늘]). 누를 때 다시 따져서 04:00 을 넘긴 것도 막음.
- 앞으로 당기기(`applyBringForward`)는 **내일**로: 오늘 복습에서 이미 푼 문항이 오늘 계획에 되돌아와 retry 로만 남아 '오늘 복습'이 계속 뜨던 것 · 아직 안 푼 문항이 오늘로 당겨져 간격이 줄던 것을 막음. 이미 내일까지 낼 차례인 문항 · 통과한 문항은 그대로. `forwardedItems` = 내일까지 나올 그 레슨 문항 수.
- API `forward` 는 기기 기록을 받지 않을 때(`taken: false` — 기기의 owner 가 다른 이용권)에도 이 이용권의 저장된 기록에 한다(구성도를 한 이 이용권의 요청). 응답에 `forwarded`. 기기 쪽은 당길 레슨을 `kig-learning-forward:<과정>` 대기열에 두고 **어느 쪽이든 다음 요청이 싣고 가서** 서버가 받으면 비움(`sync.ts` `queueForward`) — 실패한 요청의 당김이 합치기(같은 날이면 저장된 쪽)에서 사라지지 않게.
- 복습 틀(`ReviewSession`): 쪽이 **가려질 때**(다른 앱 · 잠금)는 쥔 틀린 답을 기록하지 않는다 — 돌아와 누른 '내 답도 맞아요'가 그대로 그날의 답(pending · 진도 안 깎임). 쥔 답은 기기(`kig-learning-held:<과정>`)에도 두어, 가려진 채 쪽이 죽으면 다음에 복습 · 오답노트 쪽을 열 때 **답한 시각으로** 기록(`commitLeftAnswers`). 쪽을 정말 떠날 때(pagehide · 다른 쪽으로) 기록. 쥔 답은 넘어갈 때도 답한 시각으로 기록(03:58 답 · 04:01 넘김 → 시험 날 그대로).
- 오답노트(`WrongNotes`): 쪽을 떠날 때(다른 쪽 · pagehide)도 연습을 올림 · 다시 풀기마다 신고 표시 비움 · 레슨은 한 번에 하나만 펼침(채운 '지금 다시 풀기' 하나).
- 관리자 신고 목록: 한 요청에 기록 5,000개를 통째로 읽던 것을 **쪽 단위(기록 200개)** 로 — `serverStore.ts` `listLearningReports`(읽자마자 신고만 남김 · R2 는 StartAfter · 로컬은 위치) · 라우트가 `next` 를 돌려주고 화면이 이어 불러 `review.ts` `mergeReportGroups` 로 합침. `listLearningRecords` 는 없앰(이 단계에서 만든 것 · 다른 곳에서 안 씀).

**PASS-OFF 쪽**
- 구성도는 **대주제 끝**: 서버(`passoffUnlock.ts` `applyPassoffUpdates`)는 그 대주제 레슨 조건(`passoffLessonsDone` — ceil(0.8n) + 마지막 레슨)을 채운 뒤에만 `{ mapRefillTopic }` 을 받는다(거절 이유 "not-ready" · 한 요청에 레슨과 같이 오면 레슨 먼저 — LIFE 도 같음). 과정 첫 화면의 '구성도 다시 채우기' 줄 · 진도 칸 · 잠금 화면 조건 줄 · 마지막 레슨 5단계 끝 · 구성도 쪽이 모두 그때부터 열고, 그 전에는 '대주제 레슨을 마친 뒤 할 수 있어요'(구성도 쪽은 남은 조건 · 이 기기에서 보내는 중인 완료가 서버에 닿으면 쪽을 다시 받음).
- 구성도 칸 화면은 **놓은 레슨**을 묻는다('2. 2인칭 — 이 레슨의 규칙 한 줄') → 규칙 · 문장 채점과 문장 보기도 놓은 레슨 기준(보기가 칸의 정답 레슨 것이라 배치가 틀렸다는 것을 미리 알려 주던 것 막음 · 다른 두 문장은 순서 힌트가 없는 고정 고르기). 결과 문구는 '틀린 칸의 레슨(…) 문항은 내일부터 복습에 다시 나와요'(서버가 센 수가 0 이면 '지금 복습할 문항이 없어요', 서버에 못 보냈으면 '서버 기록은 다음에 연결될 때 맞춰요').
- 구성도 기록 실패 이유를 나눔: 이 기기에 이용권 없음(확인 중이면 5초 기다림) · 인터넷 연결 없음 · 서버 오류. 서버가 받지 않았으면(레슨 전) 그렇게 말함. 이용권 없는 구성도 쪽 안내 줄에 `data-kig-paid-extra="license"`(쿠키 없이 이용권이 있는 기기는 확인 뒤 한 번 다시 불러 서버 판).
- 마지막 대주제 · 다음 대주제가 이미 열린 경우에는 'TOPIC N이 열려요' · '다음 대주제가 열리는 조건' 문구를 빼고 '대주제를 마무리하는 단계예요'. 구성도가 다음 대주제를 여는 때만 5단계 끝 구성도 단추가 채운 단추이고 끝 막대 '다음 강의'는 테두리(`lessonGate` `quietNext`) — 그 밖에는 구성도 단추가 테두리.
- ③ 이름표 문항의 답은 이름표를 붙인 꼴('quickly(부사)')로 기록 · 복습 결과 '내 답' · 결과 화면 신고 · 오답노트 '내 답'에 같게(관리자 목록의 지금 정답 꼴과도 같음).
- 관리자 'PASS-OFF 진도' 대주제 칩: 열렸고 아직 완료 전인 대주제에 '구성도 함 / 안 함'.

**시험(모두 일부러 깨서 실패를 먼저 봄)** — 숫자는 작업기록의 이 단계 행에:
