## 1. 원본 음성의 사실 (200개 모두 · `scripts/lecture/voice/extract-original.mjs`)

- `.audio` 레코드 = 726바이트 머리(선생님 이름 · 교재 이름 등) + MP3. 중등 24 kHz · 56 kbps, 고등 16 kHz · 32 kbps, 2채널 표식이지만 내용은 모노.
- **MP3 안에 2바이트 표식이 6~9프레임마다 끼어 있다**(평균 7.5프레임 = 0.18초 = 필기 1단위). ffmpeg 는 표식 앞 프레임을 깨진 것으로 보고
  버려서, 그대로 디코딩하면 24ms 구멍이 13% 생긴다(lm001: 457초 중 396초만 남음 · 경고 6,156줄). **9월에 "다 깨짐" 은 머리 + 이것.**
  프레임 머리를 따라 걸으며 표식을 빼면 경고 0 · lm001 457.176초. 200개 합 **18.14시간**(110.7~732.5초 · 평균 326초).
- 표식 수 ≈ `.gdb` 머리(172)의 길이 단위 수(200개 모두 단위 − 표식 = 1~5). 표식이 GVA 녹음기의 시계 틱 = 필기 시계. 62강에 54~65바이트짜리
  깨진 조각이 1~3개 있음(프레임 하나가 잘린 것 · 각 ≤ 24ms).
- **강의 파일의 durationSec · unitSec 가 0.15~0.3% 길었다**: ffprobe 가 표식 포함 바이트로 길이를 추정했기 때문(0.18005~0.18042초/단위).
  프레임으로 센 참값은 0.17952~0.18000(평균 0.17983). 음성이 붙으면 소리가 시계라 강의 끝에서 필기가 최대 1.7초 늦어질 뻔함 →
  `build-lecture.mjs` 가 프레임으로 세게 고침(10-17). 내용 바뀜: 강의 파일 200 + 목록(durationSec · unitSec 숫자) · pen.json 200(unitSec) —
  **pen.json 200개를 R2 에 다시 올려야 함**(upload-lecture-r2 체크포인트가 바뀐 것만 보냄). 지금 필기만 재생할 때는 차이 없음.
- 잡음(200개 · 20ms 에너지로 잼 · `.lecture-media/voice/noise.json`): 바닥 −58~−33 dBFS · 말소리 대 바닥 20.4~32.7 dB(평균 25) · 말 비율 77~85%.
  가장 시끄러운 쪽은 고등 3 · 12 · 13 · 14 · 5강과 중등 77강(바닥 −33~−36 dBFS) — 목소리 변환(길 1)은 잡음 제거를 켜야 하고, 시범에 이런 강의를 하나 더 넣을지 판단.
  소리 크기도 제각각(lm001 평균 −23 dB · lm057 −11 dB · lh082 −29 dB) — 새 음성은 −16 LUFS 로 맞춤(assemble).
