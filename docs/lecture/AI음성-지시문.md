## 1. 원본 음성의 사실 (주 세션이 200개 모두 잼)
- .gdb 안의 '<책 제목>.audio' 레코드 = 726바이트 머리 + MP3. **MP3 는 머리 뒤 첫 프레임부터**(726바이트 지점)만 잘라 써라 — 9월에 "다 깨진" 것은 앞쪽 쓰레기 바이트 · 잡음 섞인 소리 그대로를 쓴 탓. 중등 24 kHz · 56 kbps, 고등 16 kHz · 32 kbps(ffprobe `-f mp3`).
- 길이: 110 ~ 731초(평균 326초 · 전체 18.2시간). 사이트 강의 파일 `content/lessons/lecture/<id>.json` 의 `lecture.durationSec` = `lengthUnits × unitSec` = 원본 MP3 길이(차이 0.2% 안).
- 필기 시간: pen.json 의 t 는 '단위', 1단위 = `unitSec`(강의마다 0.18005~0.18042초, 평균 0.18025 — .gdb 머리 offset 172 의 u16 = 강의 길이(단위)). **원본 음성 0초 = 필기 0초**(GVA 가 함께 녹음).
- 사이트 재생: 음성이 붙으면 그 음성의 currentTime 이 시계 — 필기는 `t × unitSec ≤ currentTime` 인 것까지 그려진다. **그러므로 AI 음성은 원본과 같은 타임라인 위에 있어야 한다**: 같은 총 길이, 말이 시작 · 끝나는 시각이 원본과 같음.
- 내용: 선생님(강광진 — .audio 머리에 이름)의 한국어 설명 + 영어 지문 읽기가 섞임. 잡음 있음.

## 3. 만드는 방법 (길 2 기준 A → Z — 길 1 은 A · B · H~M 을 그대로 쓴다)
A. **원본 추출**: 강의마다 MP3(726바이트 뒤)를 꺼내 16 kHz mono WAV 로(ffmpeg 있음: `C:\Users\ghddl\AppData\Local\Microsoft\WinGet\Packages\Gyan.FFmpeg_*\…\bin`). 길이가 `lecture.durationSec` 와 ±0.2초 안인지 200개 확인.
B. **잡음 줄이기(받아쓰기용만)**: 받아쓰기 정확도를 위해 RNNoise/afftdn 정도로(9월 커밋 a986d9f3 참고). 새 음성에는 원본 소리를 섞지 않는다.
C. **받아쓰기 + 시각**: 1순위 Azure Speech(키 `AZURE_SPEECH_KEY` · `AZURE_SPEECH_REGION`=koreacentral, .env.local — 값 출력 금지) 의 단어 단위 시각이 나오는 받아쓰기(ko-KR, 영어 섞임 → 다국어/en-US 후보), 2순위 faster-whisper(설치됨 · GPU 없음 — CPU 라 느림, 시범 3강의 교차 확인용). 결과: 단어마다 시작 · 끝 시각.
D. **말 덩어리(구간) 나누기**: 0.3초 이상 쉼에서 끊어 구간(문장 · 짧은 말 단위, 대개 2~8초)을 만든다. 구간마다 `start · end · 원문 받아쓰기`. VAD(에너지/webrtcvad 류)로 말소리 구간과 대조해 빠진 말 · 잘못 붙은 말을 찾는다.
E. **받아쓰기 바로잡기**: 잡음 때문에 틀린 낱말을 고친다 — 그 강의의 교재 쪽 그림(지문 영어 원문)을 참고하고, 한국어 설명은 문맥으로. **선생님 말을 새로 쓰거나 요약하지 않는다**(말한 그대로 · 군말("어", "음")만 뺄지는 사장님께). 바로잡은 글은 강의마다 파일로 남긴다(git 밖 — 예: `.lecture-media/voice/<id>.segments.json` — 구간 · 원문 · 고친 글 · 고친 이유).
F. **목소리 고르기 — 사장님 몫**: ① 원래 선생님 목소리 복제(강광진 님 동의 · 권리가 필요 — 사장님이 정하실 일, 동의 없이 하지 마라) ② Azure 기성 목소리(예: 한국어 남성 ko-KR-InJoon / Hyunsu 계열, 다국어 목소리는 영어 지문도 한 목소리로 읽음) ③ 한국어 · 영어 목소리를 나눠 쓰기. 후보 2~3개로 같은 1강 앞 1분을 만들어 사장님께 들려 드리고 고르시게 한다.
G. **구간 길이에 꼭 맞춰 합성**: 구간마다 원본 구간 길이(end − start)에 맞춘다. Azure SSML `<mstts:audioduration value="…ms"/>`(문단 길이 지정 — 0.5~2배 안)로 합성하고, 결과 길이를 재서 ±40ms 넘으면 ffmpeg atempo(또는 rubberband)로 미세 조정. 늘이거나 줄이는 비율이 0.8~1.25 를 넘으면 그 구간은 다시 나누거나(쉼에서) 이웃 쉼을 쓰되, 말 시작 시각은 원본 그대로 둔다. 기본 말 빠르기는 원본의 초당 음절 수를 재서 맞춘다(구간마다 비율이 1 근처가 되게).
H. **이어 붙이기**: 원본 총 길이(`lecture.durationSec`, 샘플 단위로 정확히)의 무음 위에 각 구간을 원본 시작 시각에 놓는다(겹치면 안 됨). Node 에서 PCM 으로 직접 만들거나 ffmpeg adelay+amix. 소리 크기 맞춤(−16 LUFS 근처 · 피크 −1 dBTP).
I. **인코딩**: 한 번만 인코딩. MP3 는 앞에 인코더 지연(수십 ms)이 붙으니 재고 보정하라(LAME 의 gapless 정보 · 또는 지연만큼 앞을 당겨 둠). 최종 파일 길이 = `lecture.durationSec` ± 0.05초.
J. **자동 검사(강의마다, 숫자로)**: ① 총 길이 차 ≤ 0.05초 ② 말소리 구간 대조 — 원본 말 시작 시각의 95% 이상에 새 음성 말 시작이 ±0.3초 안 ③ 구간 안 늘이기 비율 0.8~1.25 밖 0개 ④ 무음에서 튀는 소리 0 ⑤ 필기 싱크 표본: 선생님이 영어 낱말을 쓰는 획(예: 1강 'David' · 'first' · 'middle' · 'last')과 그 낱말을 말하는 구간이 겹치는지 강의마다 5곳 이상 ⑥ 깨기 시험 — 일부러 0.5초 밀린 파일로 ①·② 가 FAIL 나는지.
K. **시범**: 중등 1강(lm001) · 57강(lm057 — 쪽 넘김) · 고등 82강(lh082 — 쪽 기록 없이 시작) 3개를 먼저 끝까지 만들어, 사이트(로컬)에서 필기와 함께 재생해 사장님께 들려 드리고 확인받는다. 확인 전 200강 일괄 금지.
L. **사이트에 붙이기**: R2 키 `audio/lecture/<id>/voice.mp3`(비공개 버킷 — `upload-lecture-r2.mjs` 는 지금 jpg · json 만 올리니 mp3(audio/mpeg)를 더하라). 강의 파일에 `lecture.audio = { src: "/audio/lecture/<id>/voice.mp3", … }` — **주의: `build-lecture.mjs` 는 강의 파일을 .gdb 에서 다시 쓰므로 그대로 두면 audio 가 지워진다.** 음성 목록 파일(예: `docs/lecture/voice-manifest.json` — 경로 · 길이만, 글 없음)을 build-lecture 가 읽어 audio 를 넣게 고쳐라. 무료 강의(lm001 · lm002)의 음성 키는 `node scripts/buildFreeSpeechKeys.mjs` 가 freeMediaKeys 에 넣는다(이미 `lecture.audio.src` 를 읽음 — 확인). 유출 도구(probe-bundle-leak-all · probe-entitlement-all · check-media-gate · paidLeakCheck)는 `lecture.audio.src` 를 이미 바늘로 씀 — 다시 돌려 0 확인.
