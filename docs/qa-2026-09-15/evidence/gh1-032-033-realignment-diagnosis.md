# gh1-032 / gh1-033 재정렬 — 진단만 (적용 보류)

**상태: 보류 (2026-09-16 ~ 09-17). 오늘 이동하지 않는다.**

## 왜 보류하는가

두 페이지는 문항 번호와 문장이 어긋나 있어 보인다. 다만 이 어긋남은
**두 페이지를 나란히 놓고 대조해야** 확정되는 종류다. 지금 추론으로 15칸을
옮기면, 내일 원본 아카이브(`H:/랩자료모음/…`)를 받았을 때
**어느 쪽이 맞는지 대조하기가 더 어려워진다** — 이동한 뒤에는 원래 상태로
되돌릴 근거가 사라지기 때문이다.

따라서 오늘은 진단만 남기고, 실제 이동은 아카이브 수령 후로 미룬다.

## 현재 관측

`docs/qa-2026-09-15/scripts/report-kig006.cjs` 의 `POLLUTED_REPAIRS` 에
`gh1-032 #36~39` 4건이 REALIGN 으로 등록되어 있다. 그중 `#36` 은
문장 번호 `37.` 이 셀 안에 붙어 들어온 형태다:

```
current: "Don't I love her(Do I not ---)? 37.This is mine."
text   : "Don't I love her(Do I not ---)?"
alt    : "Do I not love her?"
why    : "stray sentence number '37.' glued in; see gh1-032 realignment"
```

## 확인이 필요한 것 (내일, 아카이브 대조)

1. `gh1-032` 와 `gh1-033` 의 **원본 셀 번호 대응**이 1:1 인지, 아니면
   한쪽이 한 칸 밀려 있는지.
2. 밀렸다면 **어느 방향으로 몇 칸**인지 — `#36~39` 4건만인지, 15칸 전체인지.
3. 이동 대상이 `text` 뿐인지, `n` 번호까지 바뀌는지.
4. `gh1-032 #36` 의 `37.` 이 **다음 문항의 번호가 잘못 붙은 것**인지,
   실제로 `#37` 이 이 셀에 속하는지.

## 결정 규칙 (합의된 것)

- 판정이 갈리면 **짝 페이지의 한국어를 근거로 삼는다** (KIG-006 규칙과 동일).
- 이동은 **추론으로 하지 않는다** — 원본 아카이브와 대조한 뒤에만 한다.
- 이동 스크립트는 `apply-kig006.cjs` 처럼 **재실행 가능**하게 작성한다
  (`extract.mjs` 가 레슨 JSON 을 통째로 덮어쓰므로).

## 재개 지점

1. 아카이브 수령 → `scripts/extract.mjs` 로 재추출.
2. `gh1-032`/`gh1-033` 원본 셀을 나란히 덤프해 번호 대응 표를 만든다.
3. 위 4개 질문에 답한 뒤, 이동량과 방향을 확정한다.
4. `docs/qa-2026-09-15/scripts/realign-gh1032.cjs` 를 작성해 적용한다
   (오늘은 작성하지 않는다 — 이동량이 미확정이라 의미가 없다).
5. `apply-kig006.cjs` 를 실행해 `text` + `alternatives` 를 기록한다.
