### 🔴 RE-011 (P1) — 모든 페이지가 자신을 "홈페이지의 사본"이라고 선언함

`src/app/layout.tsx:21-22`

```ts
alternates: {
  canonical: "/",
},
```

이 값을 **어떤 하위 페이지도 덮어쓰지 않습니다**(`src/app` 전체에서 `canonical` 정의는 이 한 곳뿐).
따라서 운영의 모든 페이지가 다음을 내보냅니다.

```
/                → <link rel="canonical" href="https://k-ig-core.vercel.app">
/t/ld            → https://k-ig-core.vercel.app
/ld              → https://k-ig-core.vercel.app
/ld/d001         → https://k-ig-core.vercel.app
/reading/pr001   → https://k-ig-core.vercel.app
/student/s1-1    → https://k-ig-core.vercel.app
```

canonical은 검색엔진에게 **"이 URL의 정본은 저쪽이니 이 페이지는 색인하지 말라"**고 말하는 태그입니다.
지금 상태는 사이트맵으로 1,750개 URL을 색인해 달라고 제출하면서, 그 페이지들이 전부
**"우리는 홈페이지의 중복"**이라고 답하는 모순입니다. 사실상 **홈 한 장을 제외한 전 사이트가
검색에서 배제**됩니다.

상품화 단계에서 자연 유입을 기대한다면 이것이 가장 먼저 고쳐야 할 항목입니다.

조치: 각 페이지의 `generateMetadata`에서 자신의 경로로 canonical을 설정
(`alternates: { canonical: `/${course}/${lesson}` }`). 루트 레이아웃의 전역 canonical은 제거.

> Ava `200 immutable` · Range `206` · 범위초과 `416 no-store`.


없는 음원을 요청하면 이렇게 응답합니다.

```
GET /audio/azure-ava/v1/deadbeefdeadbeef.mp3

HTTP/1.1 401 Unauthorized
Cache-Control: public, max-age=31536000, immutable      ← 오류인데 1년 캐시
Content-Type: text/html                                  ← R2의 오류 HTML이 그대로
```

원인이 두 겹입니다. **둘 다 커밋 `91cc15b`~`0f7a1c4`에서 들어온 회귀입니다.**

**(1) S3의 404를 설정 오류로 오인해 공개 URL로 재시도**

`src/lib/mediaOrigin.ts`의 `catch`는 416만 구분하고 **나머지를 전부 폴백**시킵니다.

```ts
if (status === 416) return { status: 416, ... };
return fetchFromPublicUrl(key, range);   // ← S3가 404를 준 경우도 여기로
```

객체가 실제로 없으면 S3는 404를 줍니다. 그런데 이것이 "자격증명 문제일 수도 있으니 폴백"으로
처리되어 공개 URL을 다시 부르고, 그 URL은 이제 꺼져 있으므로 **R2가 401 HTML**을 돌려줍니다.
결과적으로 없는 파일이 404가 아니라 **401 + 남의 오류 페이지**가 되고, 매번 무의미한 왕복이
한 번 더 발생합니다.

**(2) 성공 경로의 캐시 헤더가 오류 응답에도 붙음**

`src/lib/mediaRoute.ts`는 404와 416만 `no-store`로 처리하고, 그 외 상태는 성공으로 간주해
`public, max-age=31536000, immutable`을 붙여 반환합니다. 그래서 **401·403·500 같은 오류가
CDN에 1년간 고정**됩니다.

이쪽이 더 위험합니다. 어떤 이유로든(일시적 S3 오류, 배포 중 자격증명 공백 등) 한 번 실패한
클립 URL은 **모든 사용자에게 1년 동안 깨진 상태로 제공**됩니다. 자가 복구가 되지 않습니다.

조치:
1. `fetchMediaObject`의 `catch`에서 **S3 404는 그대로 404로 반환**하고 폴백하지 않는다.
   폴백은 인증·설정 실패(403 `AccessDenied`)와 네트워크 오류에만 적용한다.
2. `handleMediaRequest`에서 **200/206에만** 장기 캐시를 적용하고, 그 외 상태는 `no-store`로 한다.

검증: 없는 키 요청이 `404` + `Cache-Control: no-store`여야 하고, 정상 클립은 200 + 장기 캐시를
유지해야 한다.

## 3-B. 유출된 비밀값의 실제 범위 (2026-09-16 확인)

작업 중 `.env.local`이 화면 캡처로 노출되었습니다. 그 파일에 실제로 들어 있던 변수는 **6개**입니다.

| 노출됨 — 교체 필요 | 노출되지 않음 |
|---|---|
| `R2_ACCOUNT_ID` · `R2_ACCESS_KEY_ID` · `R2_SECRET_ACCESS_KEY` · `R2_BUCKET_NAME` | `LICENSE_SECRET` |
| `ADMIN_PIN` · `ADMIN_SESSION_SECRET` | `LICENSE_SALT` |
| | `LICENSE_STORAGE_SECRET` · `R2_LICENSE_BUCKET` |

**이용권 서명 키(`LICENSE_SECRET`·`LICENSE_SALT`)는 유출되지 않았습니다.** 이 둘은 Vercel에만
설정되어 있습니다. 유출됐다면 누구나 유효한 이용권을 무한히 만들 수 있었으므로, 이 점은 중요합니다.

교체가 필요한 것은 R2 토큰과 관리자 자격 2개입니다. R2 토큰은 **모든 버킷 읽기·쓰기** 권한이라
그대로 두면 비공개 버킷 전환이 무의미해집니다.

## 3-C. 소유자가 직접 확인한 것 (2026-09-16)

**실제 학습 흐름은 소유자가 브라우저에서 직접 전 과정을 조작해 확인했으며, 문제가 없었습니다.**

이 세션의 검사는 전부 정적 분석과 HTTP 요청이었으므로, "버튼을 눌렀을 때 실제로 소리가 나는가",
"채점이 화면에서 동작하는가", "단계 이동이 끊기지 않는가" 같은 것은 확인할 수 없었습니다.
오늘 서버 게이트·미디어 게이트·음성 엔진·채점 로직이 모두 바뀌었기 때문에 이 확인이 필요했고,
소유자가 수행했습니다.

**다시 하지 마세요.** 코드가 또 크게 바뀌면 그때 다시 확인하면 됩니다.
