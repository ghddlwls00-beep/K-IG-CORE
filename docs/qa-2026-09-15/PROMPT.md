## 작업 규칙

1. 이슈 **하나씩** 처리합니다. 수정 → PROGRESS/README에 적힌 완료 조건 실행 → 결과 보고 → 커밋(`fix(KIG-005): ...`). 다음 이슈로 넘어가기 전에 확인받으세요.
2. **검증하지 않은 것을 완료라고 하지 마세요.** 실행한 명령과 출력을 그대로 보여주세요. 가장 확실한 방법은 **수정을 되돌렸을 때 같은 프로브가 실패하는지** 확인하는 것입니다. 2차 세션은 전 항목을 그렇게 검증했습니다(PROGRESS.md §4 참조).
3. **데이터를 지워서 "해결"하지 마세요.** 원본이 기준입니다. 원본을 구할 수 없으면 그 사실을 알리고 해당 기능 비노출을 제안하세요.
4. **🔴 문장·단어 텍스트를 바꾸면 음성 클립을 반드시 다시 구우세요.** 클립 키가 텍스트 해시라서, 텍스트가 바뀌면 그 문장은 소리가 나지 않습니다. KIG-002가 이 방식으로 READING 음성을 40.6%까지 떨어뜨렸습니다. 절차는 PROGRESS.md §3 끝에 있습니다. 그룹 C·D는 대부분 여기 해당합니다.
   - **음성 작업 전에 `.env.local`이 있어야 합니다.** 이 파일은 비밀값이라 GitHub에 없습니다. 소유자에게 요청하세요. `public/audio`도 gitignore라 클론에는 클립이 2개뿐인데, 자격증명이 있으면 스크립트가 R2를 조회해 실제 보유분(38,398개)을 인식합니다. 자격증명 없이 생성을 돌리면 전 코퍼스를 다시 구우려 하고 무료 한도(월 50만 자)를 2.5배 초과합니다 — 스크립트가 경고하지만, 경고를 무시하지 마세요.
5. **UI 문구를 새로 쓸 때 음성의 출처를 언급하지 마세요.** "원어민 음성"도, "AI 음성"도 쓰지 않습니다. 기능만 설명하세요("음성 듣기", "발음 듣기"). 소유자 결정입니다(PROGRESS.md §1-B).
6. **운영 데이터에 쓰지 마세요.** Cloudflare R2 버킷과 Vercel 환경변수는 건드리지 않습니다. 로컬 유료 레슨 검증은 PROGRESS.md §5의 절차를 쓰세요(작업 후 fixture 파일 삭제 필수).
7. **`.env.local`과 `.vercel/`의 값은 절대 출력하거나 커밋하지 마세요.** 스크린샷도 안 됩니다.
8. `main`에 push하면 Vercel이 자동 배포됩니다. 배포 후 운영 URL에서 재확인하세요.
9. PROGRESS.md §4 "환경 함정"을 먼저 읽으세요. Tailwind 캐시, dev origin 제한 등 시간을 크게 잡아먹는 함정이 정리되어 있습니다.

10. **🔴 세션이 끝나기 전에 반드시 인계 기록을 남기세요.** 이 작업은 여러 AI가 이어받습니다. 당신의 대화 기록은 다음 사람에게 전달되지 않고, **레포에 커밋된 것만 남습니다.**
    - 사용량 한도가 가까워지거나, 작업을 멈추거나, 사용자가 "정리해"라고 하면 **그 즉시** 아래를 하세요.
    - `docs/qa-2026-09-15/PROGRESS.md`에 추가할 것: **완료한 이슈**(커밋 해시·검증 결과·측정 수치), **작업 중이던 이슈와 어디까지 했는지**, **새로 발견한 결함**, **막힌 것과 그 이유**, **다음 사람이 바로 이어받을 지점**.
    - 반쯤 고친 코드를 그대로 두지 마세요. 완성해서 커밋하거나 `git restore`로 되돌리거나 둘 중 하나입니다. 어중간한 상태를 넘기면 다음 사람이 그게 의도인지 실수인지 알 수 없습니다.
    - 마지막에 **커밋하고 `git push origin main`** 하세요. 푸시하지 않으면 없던 일이 됩니다.
    - 검증에 쓴 스크립트는 `docs/qa-2026-09-15/scripts/verify/`에 커밋하세요. 다음 사람이 같은 것을 다시 만들지 않아도 되고, 회귀 확인에도 씁니다.
